# Incident-server fixtures: the real Gavarres fire (recorded mode)

Generated by `scripts/make_gavarres_trigger.py` from committed fixtures only (never `data/`).
Regenerate with:

    .venv/bin/python scripts/make_gavarres_trigger.py

Run the incident server on it (no telephony, no LLM):

    python -m fireline.incident_server serve --data-dir data/gavarres-real --settings fixtures/incidents/gavarres_real/settings.json
    python -m fireline.incident_server trigger --file fixtures/incidents/gavarres_real/trigger-0001.json   # then -0002, -0003

`/api/state` then carries the real satellite perimeter as `fire_geometry` (`fire_geometry_kind: perimeter`,
`input_mode: recorded`).

## What is real

- `trigger-0001..0003.json`: three REAL Deepfire satellite perimeters of incident
  `5769dcea-385a-4ee5-9313-804f55ddb5fa` (July 2026), from the recorded response
  `fixtures/fire/deepfire/real/20260919T131342Z_satellite-perimeters.json`, split into one
  `fire_input.parse_deepfire` FireUpdate per perimeter exactly as `scripts/make_snapshots.py` does for
  `fixtures/snapshots/gavarres_real_0001..0003.json` (same picks: first, middle, last by provider
  `computed_at`; 48, 42 and 56 vertices). `as_of` is that perimeter's provider `computed_at`;
  `fire.observed_at` is its `observed_watermark`. Both increase from trigger to trigger.
- `catalog.json`: 180 real Gencat register rows (111 located, 69 care homes / campsites without
  coordinates), the union of the `assets` of those three committed snapshots, one row per `asset_id`,
  sorted. Only identity, location, occupancy, municipality and register provenance are kept; every
  per-snapshot derived field (distance, forecast, arrival, evacuation, value at risk, review flags) is
  stripped so `assess_fire` recomputes it per trigger. The catalog comes from the committed snapshots
  rather than the register extract because the extract lives in the gitignored `data/`.
  With `search_radius_m` 10000, 71 / 83 / 84 located facilities fall inside the radius of the three
  perimeters; the unlocated rows are retained for review as the contract requires.

## What is not real

- No forecast: the recorded Deepfire fire-spread run (`*fire-spread-simulation-latlon_12h_5members.json`)
  was computed on 2026-09-19 from a simulated ignition, and `assess_fire` rejects a forecast issued after
  the trigger's July `as_of`, so `spread` is not attached and every asset stays `forecast_unavailable`.
  Nothing is inferred from distance.
- No calls, no contacts, no approvals (`call_mode: disabled`, empty `contacts` / `approvals`).
- No operational evidence (no teams, destinations, roads or reservations); the state reports
  `operational_inputs_need_refresh` until an operations update bound to the current snapshot arrives.
- No LLM assessment (`llm_assessment.mode: disabled`).
- The register extract (2026-09-19) postdates the fire (July 2026): this is a recorded-input demo, not a
  historical as-of replay.
